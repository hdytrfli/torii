# Torii

Torii is a self-hosted media renamer for curated downloads. It watches folders
for new releases, resolves metadata, keeps uncertain matches in a review queue,
and moves, copies, or hardlinks approved files into a Jellyfin-compatible
library.

It is built for libraries managed without Sonarr or Radarr, where release names
are inconsistent and a wrong match is worse than a queued file. Torii automates
the repetitive parts — parsing, metadata lookup, path generation, and file
operations — while preserving an explicit human approval step.

## How it works

1. **Ingest.** A background scanner watches the movie and TV download folders
   on a configurable interval. It ignores partial downloads, temporary files,
   unsupported extensions, and files that have not stopped changing.
2. **Identify.** `guessit` parses the release name, local `.nfo` metadata is
   read when present, and Jellyfin RemoteSearch supplies provider candidates.
   AI is only used when there are no Jellyfin or NFO candidates, or when
   explicitly requested. TMDb, IMDb, and TVDB IDs can also be entered manually.
3. **Review.** The FastAPI backend stores jobs in SQLite and exposes them over a
   bearer-token JSON API. The React queue provides filters, sorting, row
   previews, metadata editing in a side sheet, bulk approve/reject, and undo.
4. **Apply.** Approved jobs are moved, copied, or hardlinked into the library.
   Torii refuses to overwrite an existing target, carries sidecar files along
   with the video, cleans up empty source folders, and records enough state to
   undo a completed apply.
5. **Name.** Naming layouts are composed from draggable tokens and plain text,
   with live previews generated by the API before anything is applied.
6. **Authenticate.** Passwords are hashed with `scrypt`, sessions are stored
   server-side, and administrators can manage users and passwords from the web
   UI.

The API and scanner live in `apps/api`; the React frontend lives in `apps/web`.
The production image builds the frontend and serves it from FastAPI, so the app
runs as a single container.

## Features

- Watches movie and TV download folders on a configurable interval.
- Resolves metadata through Jellyfin RemoteSearch, local `.nfo` files, filename
  parsing, and optional AI fallback.
- Keeps uncertain matches in a review queue with filtering, sorting, bulk
  actions, row previews, and undo.
- Supports manual identification by TMDb, IMDb, or TVDB ID.
- Provides naming layouts with draggable tokens and live previews.
- Moves, copies, or hardlinks approved files into a Jellyfin library.
- Cleans up empty source folders after successful applies.
- Includes multi-user authentication with administrator controls.
- Stores jobs, users, and settings in SQLite.
- Runs as a single Docker container with Docker Compose.

## Deploy

Torii can be deployed in several ways. See
[docs/deployment.md](docs/deployment.md) for details.

- Build from source with Compose: `docker compose up -d --build`
- Pull the published image from GHCR
- Run the container directly with `docker run`

The default Compose file publishes <http://localhost:8090>, mounts `./temp` at
`/media`, and stores the database under `/data`. Adjust those paths for your
download and library layout.

## Next goal

The next major goal is a **companion app** for reviewing and approving jobs away
from the desktop. The existing JSON API already covers authentication, jobs,
metadata, bulk actions, and undo, so the companion can focus on notifications
and a fast mobile review workflow rather than reimplementing the rename engine.
